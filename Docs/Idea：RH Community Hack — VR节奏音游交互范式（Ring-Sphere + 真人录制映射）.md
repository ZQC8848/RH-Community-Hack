## 项目

RH Community Hack

## 1. 一句话概括

一个 VR 节奏舞蹈音游：玩家手持 controller，跟随音乐节拍伸入空间中出现的 sphere 完成击打；sphere 的生成时间与三维位置直接来自真人跳舞时的手柄录制轨迹，无需人工编排关卡。

---

## 2. 核心交互范式

### 2.1 单个 beat 的呈现

- 每个 beat 对应一个 **sphere**：玩家把 VR controller 伸入 sphere 内即完成这一拍。
- sphere 外部套一个更大的 **ring**（提示环）：ring 随时间收缩/逼近 sphere，作为节奏的预先视觉提示（类似 Beat Saber 的"来球"预警，但用同心环收束代替飞行接近）。
- 判定分三档（Perfect / Good / 超时未命中），Ring 渲染为 billboard，美术方向定为"霓虹能量脉冲"（Fresnel 发光 + emission，判定等级用颜色区分）。判定状态机、判定窗口、策划可调变量表等实现级细节见仓库内 `Docs/Ring-Sphere 交互判定与美术规格.md`（2026-08-20 起，该文件是这部分的实现规格，本文档只保留高层描述）。

### 2.2 关卡生成：真人录制映射（核心洞察）

不手动摆放 beat 关卡，而是：

1. 让一个真人戴上 VR，跟着一首歌自由跳舞 / 打拍子，全程录制 controller 的 6DoF 轨迹（位置 + 时间戳），与音乐时间轴对齐录制。
2. 后期做谱面映射时，只需要：
   - 从录制轨迹中挑选/检测节拍时刻（可基于音乐的 beat onset，或基于录制者手柄速度骤变/停顿点）→ 得到每个 sphere 的**生成时间**。
   - 该时间点对应的真人 controller 位置 → 直接作为这个 sphere 的**空间位置**，无需额外设计。
3. 也就是说，"录人跳舞"这一步同时解决了节奏关卡设计里最难的两件事——**时间点选取**与**空间走位设计**——把关卡编排问题转化成了"找一个人对着歌跳得好看"的问题。

### 2.3 潜在优势

- 关卡设计门槛从"谱面设计师 + 3D 空间编排"降低为"找一个跳得好/有节奏感的人录一遍"。
- 生成的击打点天然符合人体可达范围与自然舞蹈动线,不会出现程序生成谱面里常见的"物理上别扭"的位置。
- 换真人示范者 = 换关卡风格/难度，理论上可以做成低成本的 UGC 谱面管线。

## 3. 待解决 / 下一步

- [ ] beat 时刻的自动检测算法：音乐 onset detection vs. 手柄运动特征（速度峰值/加速度骤变/停顿），或两者加权融合
- [ ] ring 收束的时间提前量（lead time）如何标定，保证不同 BPM 下提示节奏一致
- [ ] 位置直接复用真人轨迹是否需要做空间归一化（不同身高/臂展的玩家 vs 录制者）
- [ ] 命中判定容差（sphere 半径、controller 进入判定方式：中心点 vs 碰撞体）
- [ ] 双手/多 sphere 并行节拍的情况如何处理（同一时刻多个 beat）
